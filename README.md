# Student Service Request Monitoring (Streamlit)

A classroom demonstration app for Section B: Student Service Request Monitoring. It explores request delays/workload and estimates whether an SLA breach may occur.

## Included files

- `train_model.py` — trains and evaluates a scikit-learn preprocessing + Random Forest pipeline.
- `app.py` — Streamlit app with Home, Dataset, Data Analysis, Prediction, Dashboard, and System Design pages.
- `requirements.txt` — Python dependencies.
- `student_data.csv` — synthetic demonstration dataset.
- `student_model.pkl` — fitted pipeline generated from the included synthetic dataset.
- `model_metrics.json` — evaluation metrics generated by `train_model.py`.
- `.gitignore` — excludes common local and sensitive files.

## Important: adapt this to your actual midterm work

The laboratory instructions require reuse of the **actual midterm target, features, dataset, preprocessing, trained model, and results**. This package is a working starter/demo because the supplied exercise sheet does not include your midterm notebook, dataset, or saved model. The included data and metrics are synthetic and must not be presented as actual school results.

Before submission:
1. Replace `student_data.csv` with your authorized midterm dataset, preserving the exact training columns or updating the code to match them.
2. Update `FEATURES`, `TARGET`, preprocessing, and model code in `train_model.py` to match your midterm pipeline.
3. Reuse the original fitted pipeline when available; do not retrain on every app refresh.
4. Run `python train_model.py` to regenerate `student_model.pkl` and `model_metrics.json`.
5. Verify predictions against the same test cases from your midterm notebook.
6. Use synthetic or properly authorized data for public deployment. Do not commit passwords or sensitive student records.

## Setup

Python 3.9+ recommended.

```bash
python -m venv .venv
# Windows:
.venv\\Scripts\\activate
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
python train_model.py
streamlit run app.py
```

Open the local URL printed by Streamlit.

## Dataset schema in this demo

| Column | Meaning |
|---|---|
| `days_open` | Number of days the request has remained open |
| `current_workload` | Approximate active workload for the responsible staff/queue |
| `submitted_hour` | Hour of submission (0–23) |
| `request_type` | Type of student service request |
| `priority` | Request priority |
| `department` | Responsible service department |
| `sla_breach` | Target label: 1 = breach, 0 = no breach |

These are illustrative demo fields, **not confirmed midterm fields**.

## Model limitations and human review

The model is trained on synthetic sample data, so its metrics and predictions do not establish real-world accuracy. Predictions are decision-support outputs only. Student-services staff must verify records, applicable SLA rules, and context and make the final authorized decision. The starter app does not implement authentication or persistent decision logging.
